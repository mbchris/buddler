Buddler: Agentic home automation, mapped to the IBM AI Architect profile

A sentence like "I'm feeling cold" is turned into an observed, knowledge-backed decision for a Homematic home: the agent reads room, clock and weather, matches curated symptom → action knowledge (Postgres/pgvector) and then acts on the thermostat within hard bounds, or advises. Every step is traced.

2 · Workflows (LangGraph): Resolve acts or advises, Train curates knowledge

Resolve mixes LLM steps (understand, agent, decide) with deterministic ones (observe, retrieve, evaluate, act). The LLM only chooses among pre-evaluated candidates by ref; device parameters come from confirmed knowledge. Train curates knowledge with a human in the loop; Resolve only reads it.

3 · Agentic AI: bounded tool loop and guarded actuation (Resolve, steps 6–8)

Structured-output loop on the llm/ port: each step is one validated JSON decision, query (SQL on curated read-only views via MCP), read_room (climate of another room) or finish. The agent has no device-write tool: writes happen only in act, after the guard. Notes in yellow mark the requirements shown at that point.
